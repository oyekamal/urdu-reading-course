# Teacher side vs. the restructured learner path — review

Scope: `mobile/src/teacher.js`, `course/unit_NN.md` (generated by `scripts/build_course.py`), `course/00_design.md`,
against the Duolingo-style path in `mobile/src/path.js` (learned-only rule, preview words excluded from
production drills, per-letter lesson sequence, unit-level lesson bubbles: rules → letters → [marks unit 1] →
join → blend → words 1/2 → [nonjoin unit 4] → read → [marks2 unit 10] → [sight/nastaliq unit 11] →
[test unit 12] → quiz/done, see `lessonsFor()` at `mobile/src/path.js:8-25`).

No files were edited. `mobile/` was only read, never run.

## Findings, ordered by impact

### 1. Printed "Check" and "Dictation" sections can include words with untaught letters — grading is not equivalent to the app
`scripts/build_course.py:60-94`. `unit_md()` builds `words = [w4(w) for w in u["words"]]` from the **whole**
unit word list and reuses it unfiltered for "Join it" (line 62), "Dictation" (`dict_words = random.sample(words, …)`,
line 81) and "Check" (`quiz = random.sample(words, …)`, line 89). Several units embed genuine preview words whose
`en` field is annotated `(… preview)` because they use a letter from a *later* unit — e.g. unit 3's
`ٹوپی`/`ٹماٹر` (contain `و`/`ر`, taught unit 4, `data/units.json`), unit 6's `بھائی`/`ٹھنڈا` (contain `ئ`/`ڈ`),
unit 8's `قمیض`/`خط` (contain `ض`/`ط`). `random.sample` can and will pull these into the printed "score 8/10 to
move on" quiz or the dictation list. The app deliberately excludes them from every production/recognition drill
via `spellable()` (`mobile/src/drills.js:6-7`, applied at `drills.js:49` join, `drills.js:96` dictation,
`drills.js:109` quiz) and only ever shows them, clearly labelled "peek ahead", inside Read
(`mobile/src/drills.js:61`). A teacher grading the printed check against its own answer key could mark a
child wrong for a letter that was never taught.
**Fix:** in `unit_md()`, build a `spellable_words` list using the same rule as `drills.js`'s `known()`/`spellable()`
(letters taught in this unit or earlier, plus the hamza set from unit 10) and use it for Join it (line 62),
Dictation (line 81) and Check (line 89). Keep the full `words` list only for "Read it" (line 68 onward), and
there strip the `(… preview)` annotation and add a visible "peek ahead" marker exactly as
`mobile/src/drills.js:61` does, instead of printing the raw parenthetical.

### 2. Printed unit files have no "Blend" section at all, though Blend is now a first-class graded path lesson
`scripts/build_course.py:36-95` (`unit_md()`) emits exactly 8 sections: Hear it, See it, Tell it apart, Join it,
Read it, Write it, Dictation, Check. There is no Blend section anywhere in the generator or in `special_units()`
(`scripts/build_course.py:98-209`). But the app added Blend twice: as screen 5 of every consonant letter lesson
(`mobile/src/path.js:89`, "5 blend with a long vowel") and as its own unit-level path bubble between Join and
Words 1 (`mobile/src/path.js:15`, `{id:'blend', kind:'blend', title:'Blend'}`, built out at
`mobile/src/path.js:104-106`). `course/00_design.md:57,60` documents Blend as part of the app flow, but the
printable output a teacher actually reads has no trace of it — no example syllables, no mention that children
will be graded on `ب+ا`-style blending on the phone.
**Fix:** add a "## Blend it" section to `unit_md()` generated the same way `special_units()`'s unit-4 section
is (list the consonant+long-vowel syllables available at that unit, e.g. `کا کی کو` for unit 1), so the printed
sheet has a teacher-facing equivalent of what unit-level `blend` and the per-letter blend screen drill.

### 3. `build_course.py` should gain a "path lessons" section mirroring the app, so teachers can plan against the real phone sequence
Currently a teacher sees 8 fixed print headings and has no way to know the order of bubbles a child actually
works through on the phone for that unit (e.g. unit 6 = five letter lessons, then "Breath letters" (aspirates),
then Join, Blend, Words 1, Words 2, Read, Unit check — computed by `lessonsFor()`,
`mobile/src/path.js:8-25`). Recommend porting `lessonsFor()`'s conditionals into `unit_md()` (or precomputing
in Python straight from `data/units.json`, since the logic only depends on `u.n`, `u.letters`, `u.words`,
`u.sentences`) and emitting a `## 0 · Path lessons (what the child sees on the phone, in order)` list, e.g.:
```
1. ں — nūn ghunna (letter lesson)
2. ھ — dō-cashmī hē (letter lesson)
3. Breath letters (aspirates)
4. Join them
5. Blend
6. Words 1
7. Words 2
8. Read
9. Unit check
```
This is the single highest-leverage addition for the stated goal ("a teacher can plan") and would also make
findings #1 and #2 immediately visible to whoever regenerates the docs, since Blend would have to appear in
that list even before the prose section exists.

### 4. `teacher.js`'s "We do" chorus renders every unit word unfiltered, including preview words, with no "peek ahead" cue
`mobile/src/teacher.js:200-212`, specifically `(unit.words || []).forEach((w, i) => {...})` at line 203: it maps
every word in `unit.words` straight to a clickable chorus tile with no `spellable()` filter and no stripping of
the `(… preview)` annotation (that annotation is only ever stripped for display in
`mobile/src/drills.js:61`, not here). A teacher running "We do — chorus reading of the word list" for, say,
unit 3 will have the whole class read `ٹوپی` aloud chorally alongside letters that were actually taught, with
no indication that its `و` isn't due until unit 4 — the exact scenario the "learned-only" rule in
`course/00_design.md:50` ("nothing appears on screen that has not been taught yet") was written to prevent on
the phone, now leaking into the classroom script.
**Fix:** filter `unit.words` through the same `spellable()`-equivalent before building the chorus row, or at
minimum render preview words with a distinct pill/muted style (mirroring `drills.js:61`'s "peek ahead") so the
teacher knows to treat them as a preview, not a decoding target.

### 5. `teacher.js`'s "You do" rotation instructions never mention Blend, so a teacher won't route any group to it
`mobile/src/teacher.js:216-221`: the three rotation bullets are "Tell-apart and Join-it drills" (letters band),
"Read and Dictation drills" (words band), and repeated passage reading (sentences/fluent band). Blend — now a
scored, independent phone activity for every consonant-with-vowel unit — is absent from all three bullets. A
teacher sending the "letters" band to "Learner mode" has no instruction to also have them do the Blend lesson.
**Fix:** add Blend to the letters-band bullet, e.g. `"letters" band: Tell-apart, Join-it and Blend drills in
Learner mode, this unit's letters.`

### 6. `teacher.js`'s Lesson script could name the actual phone lesson bubbles instead of only the generic three-part rotation
Per the review prompt's own example: teachers should be told something like "children rotate through the
alif, be, kāf lessons on the phone" rather than only the generic band description. Currently
`mobile/src/teacher.js:213-222` (the "You do" card) gives band-level drill names only; it never lists the
per-letter lesson titles (`mobile/src/path.js:11`, one lesson per `u.letters` entry, titled `l.name`) a teacher
could point specific children at. Once #3 is done (a computed path-lesson list is available from the printed
files or could be threaded into `ctx.C`), `renderLesson()` could append a line such as "Letters band today:
open the {L.name} lesson for each child at their own letter" using `unit.letters.map(c => C.by[c].name)`.

### 7. `scripts/build_course.py:3` docstring is stale relative to the restructuring
`"""Build course/unit_NN.md lesson files from data/letters.json + data/units.json. Each unit follows the
8-step lesson shape in course/00_design.md and embeds the rendered cards and audio."""` — this still describes
the pre-restructuring flow as if it were complete and current. Once Blend is added (#2) it will be a 9-step
shape, and once path lessons are added (#3) the docstring should say the file also carries a path-lesson index
that is not one of the graded steps. Low effort, but leaving it as-is will mislead the next person who touches
this generator.

### 8. `course/00_design.md:64` claims the printable files "keep the eight-step outline for teachers" without flagging what's dropped
`"The printable course/unit_NN.md files keep the eight-step outline for teachers; the app is the learner's
path."` This line is presented as an intentional, complete simplification, but per #1 and #2 it silently drops
two things the app enforces: the learned-only/preview-word exclusion rule, and the Blend lesson entirely. As
currently worded, a reader has no reason to suspect either gap exists. Recommend rewording to something like:
"…eight-step outline for teachers (plus a path-lessons index, see §3); word selection for Dictation/Check is
filtered to spellable words only, matching the app, and preview words are marked, not silently included."

### 9. `teacher.js`'s `GROUP_ACTIVITY` unit ranges ("letters" = units 1–5, "words" = units 6–10) don't match the course map — units 6–9 still teach new letters
`mobile/src/teacher.js:10-16`. Per `course/00_design.md:34-42`, units 6 (ں ھ), 7 (ڈ ڑ ز ژ), 8 (ف ق خ غ ع ح) and
9 (ص ض ط ظ ذ) all introduce new letters, but `GROUP_ACTIVITY.words` describes units 6–10 as pure "read and
dictation" decoding practice. This predates the path restructuring, but it compounds finding #5: a teacher who
routes a "words"-band group straight to read/dictation stations for unit 6–9 will skip both Tell-apart and the
newly-added Blend lesson for that unit's new letters, even though those letters are still being freshly taught.
**Fix:** either recompute the band↔unit mapping from `u.letters.length` at each unit (data-driven, immune to
future re-ordering) or at minimum extend the "words" description to mention new-letter units still need
letter-band rotations.

### 10. `teacher.js`'s "I do" card doesn't mirror the per-letter screen order the child sees right after (forms-by-position, confusable-letter contrast)
`mobile/src/teacher.js:181-199`: for each new letter it only offers "Play name" / "Play word" buttons — it
never surfaces the confusable-letter set (`L.confusable`, used for path.js's screen 2 "tap the sound among
look-alikes", `mobile/src/path.js:83`) or the four positional forms shown with real highlighted words
(path.js screen 3, `mobile/src/path.js:85`) that `scripts/build_course.py`'s own "Tell it apart" step already
surfaces in print (`scripts/build_course.py:50-59`, using `l["confusable"]`). Not incorrect, but a missed
opportunity for the "I do" modeling to actually preview what the child is about to do alone on the phone —
worth a one-line addition such as showing `L.confusable` letters next to the name/word buttons so the teacher
calls them out during modeling, the same look-alike framing the print version and the phone version both use.

## Not flagged as problems
- `course/00_design.md:64`'s core decision to keep a simpler print outline instead of mirroring every phone
  screen is reasonable and stated as deliberate — only the completeness of what it claims to keep (#8) needs a
  tweak, not the decision itself.
- `reader/` and `mobile/dist/` are build output (confirmed via `scripts/sync_mobile_content.sh` and
  `README.md`), not source; not reviewed for drift since they regenerate from `mobile/src/` and `course/`.
