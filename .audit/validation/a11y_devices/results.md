# Urdu Qaida mobile app: accessibility + device-shape validation (2026-10-02)

App: `mobile/` (Vite dev server :5188, git HEAD main). Read-only test, no app source touched, emulator-5554 not used.
Method: Playwright (headless Chromium 1243, touch+mobile emulation) walking 64 screens (child) / 65 (adult): onboarding, Today, unit 0, letter lesson (all sub-screens incl. tracing), celebrations, marks/join/blend/words/quiz, Review (empty, due, reveal), Read, Me, sticker book, mode picker, add-learner. 28 runs: 7 viewports x 2 tracks, font-scale 130%/200% at 320x568, 360x640, 390x844 x 2 tracks, dark mode x 2 tracks. axe-core 4.x on the 390x844 light and dark runs, aria snapshots on child 390 light and adult 390 light.

Everything below was reproduced in these runs. Not tested (no device): real TalkBack, real Android back gesture, real Android font scale, soft-keyboard PIN entry, real finger sizes.
Caveat on font scale: emulated by multiplying every element's computed font-size (like WebView textZoom), not by an OS setting.

## Files
- `walk.py` (screen walker + layout/axe/aria checks), `probes.py` (keyboard, live-region, motion, urdu, pin probes), `agg.py`.
- `runs/<track>_<WxH>_fs<scale>_<scheme>/results.json` + `shots/NN_screen.jpg` (+ `.aria.txt` for aria runs). Raw findings per screen.

## Prioritised findings

### BLOCKER (a user group cannot complete the task)
**B1. Sticker book is dead to keyboard / switch / external-keyboard users.** Screen: Me > Sticker book. Repro: open book, press Tab: focus never leaves "Back"; Enter on Back does not close it; Enter on a unit tab does not select it; only Escape works. Cause: `stickers.js:65` `o.onkeydown = e => e.key === 'Escape' && close(o)` returns `false` for every other key, and returning false from an `on*` handler calls preventDefault (confirmed `defaultPrevented=true` on Tab). Evidence: `probes/pin_child.json` (`book_still_open_after_Enter_on_Back: true`, `book_tab2_selected_after_Enter: "false"`), keyboard run `probes/keyboard_child.json` (`sticker_book_overlay.tabs = 1`). Fix: use `{ if (e.key === 'Escape') close(o); }` (braces, no return value) or addEventListener.
**B2. Teacher PIN field cannot be typed into with a hardware keyboard.** Screen: school mode > Teacher > PIN. Repro: focus the field and type 1234 -> value stays "" (`fill()` works). Cause: `main.js:100` `inp.onkeydown = e => e.key === 'Enter' && ok.click()` has the same return-false bug. Evidence: `probes/pin_child.json` (`pin_value_after_typing_1234: ""`). Soft-keyboard (Gboard, keyCode 229) behaviour not verified; Gboard numeric pads do send real key events in some versions, so this may also hit phones. Fix: same as B1.

### MAJOR
**M1. "Extra large" Urdu text setting does nothing on the learner screens.** Settings (Me/More) > Text size sets `--ur-scale`, but the setting only affects `.ur` elements without a fixed px size. Measured at scale 1 vs 1.5: NOT scaled = Today 10/12, letter intro 2/2, tell-apart tiles 2/2, Words 13/13, Read tab 1/1, Me 39/39, sticker book 48/48, (Review has no .ur). Cause e.g. `style.css:37 .word .ur{font-size:30px}`, `.tile{font-size:46px}`. Letter spacing option works (3.6px at 0.12em), joining stays intact, so only the size half is broken. Evidence: `probes/urdu_child.json` (visually identical s1 vs s1.5, `probes/sheet_urdu_words.png`). Fix: make those rules `calc(30px * var(--ur-scale,1))`.
**M2. Celebration "Next" button is off-screen and unscrollable on small/landscape screens and at large text.** Screen: celebration after any lesson. `.celebrate` is `position:fixed; overflow:hidden`; content taller than the viewport: 320x568 (button 573-629 of 568), 844x390 landscape (461-517 of 390), 390x844 at 200% text (845-922), 360x640 clipped (605-661 of 640). Mouse wheel does not scroll it (`scrollTop` stays 0). Only the "Path" chip (top-left, 88x44) remains, so the child loses the flow's main continue action. Evidence: `probes/celebrate_320x568_fs1.png`, `celebrate_390x844_fs2.png`, `runs/child_320x568_fs1.0_light/shots/28_celebrate_lesson.jpg`, results.json rule `primary-offscreen`. Also hits `celebrate_unit` ("Back to path") and `celebrate_letter` ("Next: kaf") at 320x568. Fix: make the mascot `max-height:min(40vh,...)` or `overflow-y:auto` with the button sticky.
**M3. Phone landscape (844x390) is nearly unusable in drills.** Docked primary + 4-tab bar take about 110 px of 390; the answer tiles of the tell-apart drill sit behind them, the dictation tiles are covered by "Check", onboarding demo choices sit under "See what you did" (rule `controls-overlap`, e.g. `Hear alif | Next 220x56px`, `Play word | Check`). Reachable only by scrolling a ~100 px window. The app is not orientation-locked (manifest has no `screenOrientation`). Evidence: `sheets/child_landscape_selected.jpg`, `runs/child_844x390_fs1.0_light/`. Today's "Start: Three rules" is also at y475-532 of 390. Fix: lock portrait for phones, or drop the nav and un-dock the button below 500 px height.
**M4. Large text (130% / 200%) breaks the key screens.** At 200% (any width): Today primary "Start" is 845-968 with viewport 710-866 (below the nav, `primary-offscreen`/`primary-covered`); lesson headers wrap to 3 lines; speech bubble ("Count the dots...") covers the "I see it" button (`child_fs2_selected.jpg`); play button covered by the big glyph (`obscured`: "Say be again" covered by `div.ur.big`, "Hear baa"); at 320 wide: horizontal overflow (`h-overflow`: onboarding "This is be" bubble l-13..r334, Join forms l-25), Unit titles in Units cards cut (`b` scroll 110x188 in client 110x75, 11 titles), unit labels on Today clipped (scroll 103 in 76 px), dictation "Check"/"Continue" covered by the nav. At 130% already: `primary-offscreen` 3-5 screens at 320/360 wide, 8-9 text-clipped screens. Evidence: `runs/child_*_fs2.0_light/`, `sheets/child_fs2_selected.jpg`. Fix: allow titles to wrap (`min-height` not `height`), let the lesson column scroll above a docked button with enough bottom padding, make mascot/bubble not overlay controls.
**M5. Smallest phone (320x568) is cramped but works; real defects:** Today primary "Start" covered by a nav-level button at rest (`primary-covered`), "day practised" chip clipped 46 px by the scene (`text-clipped-by-ancestor`), Play button overlapped by "I see it" in the forms screen (56x50), quiz answer rows under "Submit" (quiz/quiz_done overlap 81x56). Evidence: `sheets/child_320x568_fs1.0_light.jpg`. 360x640: only the celebration button (M2).
**M6. Focus is dropped and overlays do not manage focus.** After Enter on lesson "Continue", `document.activeElement` is `body` (focus lost; keyboard and TalkBack users restart from the top). Celebration is a plain `div` (no role=dialog/aria-modal, no focus move); Tab from it reaches lesson controls behind the overlay. Evidence: `probes/keyboard_child.json` (`focus_after_continue`), dbg run (celebrate role null, activeElement BODY, tab order reaches background). Fix: focus the heading/primary on each screen change and on celebration; `inert` the page behind.
**M7. Wrong answers are silent to screen readers.** In the tell-apart drill, a correct tap fires a polite toast "Correct: be" (role=status), but a wrong tap changes only the tile label to "alif, wrong" (no live region; the label change is not announced) and shows only visual Marko feedback. The right tile gets class `feel-answer` but no accessible "correct answer" text. Evidence: `probes/live_child.json`, tap log in this session (tap 1 produced no live text, tap 2 `status: Correct: be`). Also the toast element is created and filled in the same tick (`content.js:44`), which many SRs skip for first use (not verified). Fix: shared `aria-live=polite` region present at page load; write "Not quite, try again" / "The answer is be".
**M8. Contrast failures (axe, serious).** Light: onboarding processing step text `#a6b1bd` on `#f2f7f6` = 2.01:1; celebration chip `#f07c5e` on white 2.7:1; `.u-count` gold-deep on white 3.03; Unit pill white on `#1e9c8f` 3.38; "good" pill 3.5. Dark (80 nodes, 36 screens): active nav label `#1e9c8f` on card 4.27:1 (27 nodes, every lesson screen), unit pill `#1b8579` on `#1b4642` 2.33:1 (Today), "A whole unit" bubble 3.22:1, "Again" chip 4.27:1, combo chip white on `#2fb8a9` 2.45:1. axe also lists about 340 "incomplete" contrast checks (text over images/gradients, not decidable). Evidence: `runs/child_390x844_fs1.0_light/results.json` and `..._dark/results.json` (`axe.v`).
**M9. Focus ring too faint on light theme.** Global `:focus-visible{outline:3px solid var(--gold)}`: gold `#F2A93B` on paper `#F2F7F6` = 1.85:1, on white cards 2.0:1 (needs 3:1). The ring exists and is on every focusable (no `no_ring` hits) but is hard to see. Dark theme ratio is fine (9.6:1). Evidence: computed in this session from `style.css:4,81`.

### MINOR
- m1. Urdu text has no `lang="ur"` (`html lang="en"`, `.ur` elements with no lang attribute): TalkBack will read Arabic script with the English voice or skip it. Evidence: dbg run (`ur lang attrs []`).
- m2. Bottom tab bar: active tab not exposed (no `aria-current`/`aria-pressed`/role); not a `<nav>` landmark. Evidence: dbg run; aria snapshot ends `button "Learn", button "Review", ...` with no state.
- m3. axe best-practice: no `main` landmark (60 screens), no h1 on onboarding (23 screens), `region` (about 356 nodes), heading-order (Today h3 right after h1, 4 screens), empty table header in Progress/Me (`th:nth-child(4)`), `target-size` serious on obscured play button (`marks_intro`).
- m4. Fat-finger / child grip: "Leave lesson" X (54x48) sits 8 px right of the speaker (56x56), 16 px from the right edge, and exits instantly with no confirm (no dialog, lesson screen gone). "Next word" abuts the letter tiles with 0 px gap in build drills (`gap<6` in join_build, join_build_done, words_build); "Start" and "Back" 0 px apart in Add learner. Nav tabs touch the screen edges (l4/r4), fine for thumbs but they sit in the Android gesture zone. Add-learner colour swatches are 40x40 (8 of them, below 44). 44-47 px targets: Switch learner 82x44, "Back to path" 88x44, "Again" chip 64x44, settings checkboxes 13x48. Evidence: `layout` arrays in results.json, `/tmp` dbg run (Leave lesson).
- m5. Fonts below 11px: 10px unit-label text on Today (15-31 elements, `font<11px`).
- m6. No gesture-only controls found (pointerdown is used for feel effects only); trace canvas (`canvas.trace`) is pointer-only with no keyboard or alternative: acceptable for a handwriting drill but there is no "skip" announced in the aria tree (the lesson still has "Traced it").
- m7. Android back: app never touches history (`history.length` 2, no popstate), so the system back gesture will leave the app from any screen rather than go back. Code-evident only, not tested on device.
- m8. Tablets (768x1024, 1024x768): layout is single-column stretched to full width; tiles and mascot stay phone-sized, the docked button is 700-1000 px wide. No overflow or clipping, just poor use of space. Evidence: `sheets/child_tablet_selected.jpg`.
- m9. Infinite animations (clouds, rays, Marko loops, pgShine) run with no in-app pause when the OS does not request reduced motion: 14 running infinite animations on Today (`probes/motion_child.json`). No motion switch in Me/More.

### Checked and OK
- Reduced motion: with `prefers-reduced-motion: reduce` zero CSS/WAAPI animations and zero moving Lottie on onboarding, Today, tab switch, lesson, celebration, tile taps (11 probes). Without it animations run (e.g. 24 at celebration start). Note `fx.js`/`marko.js` read the media query once at load, so a mid-session OS change is not picked up (not tested).
- Dark mode: no white boxes or unreadable text in 64 screens; issues are only the contrast values in M8.
- Urdu rendering: Naskh and Nastaliq, scale 1 and 1.5, spacing 0/0.05/0.12em on letter intro, tell-apart and Words: no clipped ink, no overflow, joining intact at 0.12em (`probes/urdu_child.json`, `crop_spacing.png`).
- No page-level horizontal scroll at any viewport/scale; no `tap<44` on any screen except the add-learner swatches; 390x844 matches the existing `ui_audit.py` result.
- Tab order in Today/lesson/Me is logical and every control has an accessible name; letters have names like "be", "alif" and locked/wrong states ("alif, locked", "alif, wrong"). Viewport meta allows zoom.
- Keyboard: Today (26 stops), lesson and Me are fully tabbable with visible ring, no non-focusable clickables found in lesson/Me (the Today "hits" were decorative spans with `cursor:pointer`).
